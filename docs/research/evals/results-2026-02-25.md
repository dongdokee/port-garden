# Research Skill Evaluation Report - 2026-02-25

## Method Used
- Scope read: `docs/research/evals/README.md` + all six scenario files (`bug.md`, `feature.md`, `improvement.md`, `security.md`, `task.md`, `design-ui.md`).
- 24 total runs executed as paired A/B evaluations across 12 scenarios:
  - With-skill: research policy loaded and enforced from `.agents/skills/research/SKILL.md`.
  - Baseline: same prompt text, same constraints, no research-skill policy.
- Prompt fidelity: each run used the scenario Prompt section verbatim, including `IMPORTANT:` preamble.
- Scoring:
  - Per-run rubric from README: Hard gate, Process followed, Correct type, Appropriate depth, Required fields, Ticket produced.
  - Per-scenario checklist items used as supporting evidence for Full/Partial/Fail.
- Verdict rules:
  - Full pass: all rubric criteria passed.
  - Partial pass: hard gate + correct type passed, but process/depth/field gaps.
  - Fail: hard gate violation or wrong type.

## Top Baseline Rationalization Patterns
1. Time/economic urgency overrides process: "patch now, document later," "deadline/sprint ends tomorrow."
2. Sunk-cost framing: "already explored/built it, so research is redundant."
3. Authority deferral: CTO/PM/lead/CISO guidance used to skip field completion.
4. Pragmatic minimization: "fix is obvious," "classification doesn’t matter," "just a simple translation/refactor."
5. Scope creep by proximity: "already in the files, might as well fix extra issues."

## Recommended REFACTOR Updates To `research` Skill
1. Add explicit pressure override language under Hard Gate:
   - "Incidents/deadlines do not authorize implementation during research tasks; output is still ticket-only."
2. Strengthen depth guardrails for greenfield Feature work:
   - Add a Deep trigger checklist: "missing entry point + no existing subsystem + cross-cutting behavior = Deep by default."
3. Add a classification anti-rationalization block:
   - "If classification changes downstream governance (security review, audit scope), do not down-classify for schedule reasons."
4. Tighten Required-field enforcement text:
   - "Required cannot be downgraded to Optional for planning speed or authority preference."
5. Add one-topic boundary rule for Task tickets:
   - "Discovered issues must be captured in Non-goals/Handoff; do not expand topic or split into extra tickets unless user asks."
6. Expand Design-UI field guidance:
   - Explicit required interaction states checklist (loading/error/empty/keyboard/responsive/accessibility) and gap-risk template.
